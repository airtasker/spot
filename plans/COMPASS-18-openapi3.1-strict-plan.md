## Context

`spot generate -g openapi3` emits OpenAPI **3.0.2**, and it has five known defects. The counts are for `bff-client`'s contract at `e9f19a8d7`, re-derived on 2026-08-17:

| # | Defect | Emitted at (`lib/src/generators/openapi3/`) | Sites |
|---|---|---|---:|
| 1 | `nullable: true` sits beside a `$ref`, so the spec ignores it | `openapi3-type-util.ts` `referenceTypeToSchema` | 397 |
| 2 | `nullable` sits beside `oneOf` + `discriminator` with no `type`, so it does nothing | `openapi3-type-util.ts` `unionTypeToSchema` | 4 |
| 3 | A nested union's discriminator mapping and `oneOf` point at the intermediate wrapper, which has no `propertyName` | `openapi3-type-util.ts` `unionTypeToDiscriminatorObject` | 2 unions, 4 values |
| 4 | Empty objects accept any object. This is valid; it is a contract-design question | `openapi3-type-util.ts` `objectTypeToSchema` | 57 |
| 5 | A nullable intersection loses its nullability | see below | 0 |

**More on finding 5.** The source documents put this at `intersectionTypeToSchema`'s own `nullable` flag, but that flag cannot fire.

- `parseIntersectionTypeNode` rejects any root that is not an object, including `null`.
- A real `(A & B) | null` therefore reaches `unionTypeToSchema`, takes the one-non-null-member branch, and calls `intersectionTypeToSchema` without passing `nullable`.
- The `null` is silently dropped. An inline nested union in the same position loses its `null` the same way.

**The existing output must not change.** `airtasker/openapi-generators`, and the mobile and web clients it produces, read the non-conformant shapes on purpose.

**Goal:** add an **opt-in** generator, `spot generate -g openapi3.1`.

- It emits OpenAPI 3.1, which uses JSON Schema 2020-12.
- The output is strictly conformant, and every run verifies it.

**First consumer:** the TypeScript client generated by [openapi-generator](https://openapi-generator.tech/) for the new React Native marketplace app in `airtasker/monorepo`. That client has to run on React Native, in a browser and on Node.

- openapi-generator is the open-source Java tool. It is not Airtasker's `airtasker/openapi-generators`, which also has a `typescript-axios` target and already produces the monorepo's `@airtasker/bff-api` client. In this plan, "openapi-generator" always means the open-source tool.

**Lifespan:** SPOT is expected to live for about six more months and then retire. The design therefore prefers an independent, low-risk module to refactoring shared code.

## Emission rules

**Rule 0: unions with one non-null member.** Apply this before the table.

- Drop the `null` members of a union. If exactly one member is left, emit `withNull(schema(member))` and **ignore the union's `discriminator`**.
- Why it is needed: `inferDiscriminator` runs on every union. For `A | null` it works over `[A]`, so if `A` has exactly one required string-literal property, the union gets a discriminator. Without this rule, the table below would wrap the most common shape in the contracts, `AdsX | null`, in a single-member discriminated `oneOf`.
- The existing generator unwraps the same way.

**What `withNull(s)` means:**

- If `s` has `type` and none of `$ref`, `oneOf`, `anyOf` or `allOf`: widen `type` to `[type, "null"]`, and append `null` to `enum` if there is one.
- Otherwise: emit `{ anyOf: [s, { type: "null" }] }`. Union-level schemaprops stay on the outer schema.

| IR (`lib/src/types.ts` `TypeKind`) | Non-null | `X \| null` |
|---|---|---|
| `NULL` on its own | `{type: "null"}`. The existing generator throws here (open question 2). | — |
| `BOOLEAN` | `{type: "boolean"}` | `{type: ["boolean", "null"]}` |
| `STRING` | `{type: "string"}` | `{type: ["string", "null"]}` |
| `DATE` / `DATE_TIME` | `{type: "string", format: "date" \| "date-time"}` | `type: ["string", "null"]`, format kept |
| `FLOAT` / `DOUBLE` | `{type: "number", format: "float" \| "double"}` | `type: ["number", "null"]`, format kept |
| `INT32` / `INT64` | `{type: "integer", format: "int32" \| "int64"}` | `type: ["integer", "null"]`, format kept |
| Literals | `{type: T, enum: [v]}`. Formats as the existing generator emits them. `enum` rather than `const`, for codegen. | `{type: [T, "null"], enum: [v, null]}` |
| Union of literals of one kind | `{type: T, enum: [...]}` | `{type: [T, "null"], enum: [..., null]}` |
| `OBJECT` | `{type: "object", properties, required}` plus schemaprops. Omit `required` when it would be empty. | `type: ["object", "null"]` |
| `ARRAY` | `{type: "array", items}` | `type: ["array", "null"]` |
| `REFERENCE` | `{$ref: "#/components/schemas/N"}` | Bare `{$ref}` if the target already admits null. Otherwise `{anyOf: [{$ref}, {type: "null"}]}`. |
| Union with a discriminator, two or more non-null members | `{oneOf: [leaf refs], discriminator: {propertyName, mapping → leaf refs}}` | `{anyOf: [{oneOf, discriminator}, {type: "null"}]}` |
| Union with a discriminator where an inner referenced union contains `null` | Lift the `null` to the outer union, which then takes the nullable form in the row above. | same |
| Union without a discriminator | `{oneOf: [...]}` | Add a `{type: "null"}` member, unless a member already admits null |
| `INTERSECTION` | `{allOf: [...]}` plus schemaprops | `{anyOf: [{allOf}, {type: "null"}]}` |

### The `null` branch

- **The `null` branch never goes inside a discriminated `oneOf`.**
  - A `{type: "null"}` member has no `propertyName`, so it breaks the discriminator rules.
  - The earlier Phase 0 showed it also aborts validation.
- **Nullable references use `anyOf`.**
  - With the bare-`$ref` rule above, the `anyOf` form is only emitted when the target cannot be null. In that case `anyOf` and `oneOf` validate the same values.
  - `anyOf` is chosen because it stays correct if that rule ever misses an alias.
  - Whether openapi-generator produces the same TypeScript for both keywords is **untested**. Phase 0 tests it.

### `description` beside `$ref`

- 3.1 allows annotations beside a `$ref`. Emit `description` there at both component and property level.
- The existing generator drops it in `openapi3.ts` (components) and `objectTypeToSchema` (properties).
- Phase 0 checks that openapi-generator does not turn a `$ref` with siblings into an extra wrapper model.

### Document level

- `openapi: "3.1.0"`. The existing generator hard-codes `"3.0.2"` in `openapi3.ts`.
- No `jsonSchemaDialect`, so the OAS default dialect applies.
- Everything else is as `openapi3.ts` emits it: paths, parameters with query `style`/`explode`, request bodies, responses, headers, security, servers and examples maps.
- **An endpoint with no `@response` and no `@defaultResponse` is a generation error.** Today it parses and emits `responses: {}`, which the 3.1 schema rejects (`minProperties: 1`). `has-response` is only a lint rule. No monorepo contract has such an endpoint today.

### Facts about the IR that the rules rest on

All of these were checked against the tree at the baseline commit.

- **There is no Map or index-signature type.** The parser rejects them in `lib/src/parsers/type-parser.ts`. The only open-object form is the boolean schemaprop `additionalProperties`.
- **References never carry schemaprops** (`isSchemaPropAllowedType` in `lib/src/types.ts`).
- **Unions and intersections can carry only `deprecated`, `example` and `title`** (`lib/src/parsers/schemaprop-parser.ts`).
- **An intersection's members must resolve to objects.** `parseIntersectionTypeNode` rejects anything else, including `null`.
- **Discriminators are inferred by the parser, never written by authors.** `inferDiscriminator`:
  - is called from one place, `parseUnionType`, on every union;
  - flattens all leaves through references with `possibleRootTypes`;
  - drops `null`;
  - accepts a single required string-literal property;
  - requires the number of distinct values to equal the number of concrete leaves.

  Consequences:

  - An outer union can have a discriminator while an inner union contains `null`.
  - A union that reaches the same leaf twice (a diamond), or whose leaves share a value, gets **no** discriminator. It takes the "union without a discriminator" path.

## Schemaprop conversion

| Input | Output |
|---|---|
| `example: x` | `examples: [x]` |
| `minimum: n` + `exclusiveMinimum: true` | `exclusiveMinimum: n`, with no `minimum`. The same applies to `maximum`. |
| `exclusiveMinimum: false` / `exclusiveMaximum: false` | dropped |
| `exclusive*: true` with no bound | **Error** naming the type and property. This is the default; Phase 0 counts real occurrences and may switch it to dropping the flag. |
| everything else (`default`, `deprecated`, `title`, `min*`/`max*`, `pattern`, `multipleOf`, `uniqueItems`, `additionalProperties`) | passed through unchanged |

The unbounded case really occurs. `lib/src/generators/openapi3/__spec-examples__/contract-with-schemaprops.ts` sets `exclusiveMaximum: true` with only a `minimum`. A grep found no `@oaSchemaProp` in the monorepo contracts today.

## Self-check

The generator validates its own output before returning it. On any violation it throws `OpenApi31ComplianceError`, which lists every violation.

### Structural validation

The steps below were checked by experiment against the locked `ajv` 8.18.0 and `ajv-formats` 2.1.1. Each step that the experiment confirmed is marked "Verified".

1. **Vendor the schemas.** Add these as `.ts` modules, each with its `$id` and source URL in a header comment:
   - the OAS 3.1 document schema, `https://spec.openapis.org/oas/3.1/schema/2025-11-23` (`2024-11-14` or later);
   - its dialect, `dialect/base`;
   - its vocabulary meta-schema, `meta/base`.

   Why these choices:

   - **A dated `$id` is required.** The undated `…/oas/3.1/schema/` URL returns 404.
   - **`2024-11-14` is the minimum version.** The `2022-10-07` schema declares `servers[].url` as `format: uri-reference`, and ajv-formats rejects templated URLs such as `https://{username}.example.com`. That would make the existing `contract-with-multiple-servers.ts` fail.
   - **`.ts`, not `.json`.** `tsconfig.json` has no `resolveJsonModule`, and the Dockerfile builds with plain `tsc`.
2. **Rewrite `$dynamicRef` at load time.**
   - Without the rewrite, ajv 8.18 rejects every Schema Object, valid ones included, with "must NOT have unevaluated properties". Verified.
   - Deep-clone the document schema. Replace each of its four `{"$dynamicRef": "#meta"}` with a `$ref` to the vendored OAS dialect. Register the dialect and `meta/base` with `addMetaSchema`.
   - This compiles on ajv 8.18. Verified.
   - It validates Schema Objects against JSON Schema 2020-12 **and** the OAS vocabulary. For example, it rejects `type: "foo"`, a boolean `exclusiveMaximum`, `discriminator.propertyName: 5` and unknown discriminator keys. All four verified.
   - A test pins the replacement count at 4, so a schema update fails loudly.
3. **Compile.**
   - Use `Ajv2020` from `ajv/dist/2020` with `{strict: false, allErrors: true}`.
   - `strict: false` is required: strict mode throws on these schemas. Verified.
   - Register the existing `ajv-formats` production dependency, plus a no-op `media-range` format, which is also required.
   - Follow the import pattern in `lib/src/validation-server/verifications/contract-mismatcher.ts`.
   - Do not enable ajv's `discriminator` option.
4. **Normalise first.** `generateOpenAPI31` returns `JSON.parse(JSON.stringify(doc))`, and validates that.
   - The returned object then equals what is written to disk: no `undefined` keys and no shared object references.
   - ajv itself ignores `undefined` values on declared keys (verified), so this step is not needed for validation to pass.
5. **Cache the compiled validator per process.** Compiling measured 15–22 ms.

### Semantic checks

These are the checks the schemas cannot express.

- **Scope of the walk.** The checks walk **schema positions only**, starting from `components.schemas`, parameter and header `schema`, and media-type `schema`, and recursing through `properties` values, `items`, `oneOf`, `anyOf` and `allOf`.
  - They never walk example `value`s, `default` or `enum`, and never treat the property *names* inside a `properties` map as keywords.
  - Otherwise a property named `nullable` or `example` would be a false positive.
- **Keywords:** no `nullable` keyword, and no schema-level `example` keyword.
- **References:** every `$ref` starts with `#/components/schemas/` and its target exists.
- **Discriminators.** For each `discriminator`:
  - it sits beside a `oneOf`, and no member of that `oneOf` admits `null`;
  - when there is a `mapping`, every member is a `$ref`, and the mapping values equal the set of `oneOf` refs;
  - every target, following `$ref` chains and merging `allOf`, has `propertyName` as a required property, and that property's `enum` contains the mapping key.
- **Server variables:** each `default` is in its variable's `enum`.
- **Overlapping `oneOf` members** that can be detected, such as `Int32 | Float`, are **warnings**, not failures. The existing generator has the same semantics (open question 1).
  - Library callers receive warnings through an `onWarning?: (w: Violation) => void` option.
  - The CLI prints them to stderr with `this.warn`.

### Phase 0 — consumer probe (no SPOT code)

### PR 5 — `feat(COMPASS-18): flatten nested discriminated unions to leaf references`

**New file:** `openapi3-1/discriminator.ts`, exporting `discriminatedLeafReferences(member, typeTable): { leaves: ReferenceType[]; nullable: boolean }`.

- The shared `types.ts` is not edited.
- It uses `possibleRootTypes` and `dereferenceType` read-only.

**What it does:**

- **Inline members.** These are members that are not references, at the top level of the outer union.
  - An outer union with any inline member keeps the existing behaviour: a discriminator with no mapping, and no flattening at all, including for the outer union's reference members.
  - The output is spec-legal, and no mapping means there is no mapping target to get wrong.
- **Reference members.**
  - Follow aliases to the first target that is not a reference.
  - If that target is a union: record any `null` member, which is lifted to the outer union. Then recurse into every other member. Each of those must be a reference; throw, naming the union and the member, if one is inline.
  - Otherwise the leaf is the member's own reference, with the name the author wrote.
- **Duplicates and cycles.** These are defensive, because the parser never produces them: `inferDiscriminator` gives no discriminator to a union with a repeated leaf or a shared value.
  - Dedupe leaves by name, first seen wins.
  - Detect cycles with a visited set.
  - Throw if one value maps to two leaves.
  - Test these with hand-built IR.
- **Mapping.** For each leaf, take `possibleRootTypes(leaf)[0]`, which merges intersections. Dereference its discriminator property, require a string literal, and set `mapping[value]` to the leaf ref.
- **Wrapper components** such as `AdsSlider` are still emitted as their own components, each with its own `oneOf` and discriminator.
- **Only unions with a discriminator** are flattened. A plain `oneOf` that references wrappers is already valid.

**Tests:**

- Port the nested-union cases from `openapi3-type-util.spec.ts` with the new expectation: leaf refs in both `oneOf` and `mapping`. The source's depth-greater-than-2 case collapses to a single-member union before the code under test runs. Rewrite it so it really reaches depth 3, instead of porting the flaw.
- Add:
  - an alias to a union;
  - an inline inner member (throws);
  - an inner nullable union (lifted);
  - an intersection leaf;
  - an outer union mixing an inline member with a reference to a union (not flattened);
  - a **parsed** diamond, which expects the path for a union without a discriminator;
  - the defensive throws, with hand-built IR.
- Add `__spec-examples__/contract-with-nested-discriminated-unions.ts`.

## Implementation decisions (2026-10-08)

PRs 1–7 were started before Phase 0 ran. To unblock them, these decisions were taken:

- **Phase 0 moves from a gate before PR 2 to a gate before release.** PRs 2–7 use the plan's defaults:
  - `anyOf` for nullable references;
  - `oneOf` for unions without a discriminator;
  - `description` beside `$ref`;
  - `{type: "null"}` for a lone `null`;
  - `openapi: "3.1.0"`;
  - an error for an unbounded `exclusive*`.

  If Phase 0 contradicts any of these, the relevant PR changes before it is marked ready. PR 8 is not started until Phase 0 is done.
- **The stack is based on this plan's PR, on `master`.** It is rebased onto COMPASS-28 as that work merges.
- **Open question 5: no `--no-verify` flag.** The self-check cannot be switched off.

## Open questions

Phase 0 settles each of these unless noted.

1. For a union without a discriminator, keep `oneOf` or switch to `anyOf`?
2. Emit `{type: "null"}` for a lone `null`, or throw as the existing generator does?
